# 06｜測試、學習評估與發佈

## 1. 三種「有效」分開驗收

A. 軟體有效：不丟資料、不誤判、不重複排程、離線可用。
B. 內容有效：詞義、用法與答案正確，程度適合，沒有歧義測量。
C. 學習有效：**相同投入時間下，對未見、具代表性的語境選詞／閱讀題表現有改善**；有考試期限時還要考慮原始指定範圍的覆蓋。自由回想、記憶模型的預測記憶率、已學字數只是輔助指標，不能冒充考試表現。

通過 build 與 UI 測試只能證明 A 的一部分；App 內正確率提升也不能自動證明 C。

## 3. 單元與整合測試

Pure engine：
評分正規化、target 去重、狀態轉移、時計/隨機種子、到期排序、目標深度、成本混合、預算與多考試衝突。

記憶模型：
**初始 FSRS-6 baseline 的公式**與固定參考實作／版本產生的向量比較；此測試不證明語境作答轉 Good／Again 的心理學有效性。測首次 Again/Good、同日、跨日、長間隔、失敗、目標保留率、非有限/負數輸入、不同時區。
本規格包不提供假造的對照數值；M3（T014）從選定的參考實作產生對照組並保存版本。

資料整合：
用 in-memory / 暫存資料庫；實際執行 migration、交易回滾、重複事件、備份快照與 replay。
至少保留一個舊版資料檔升到最新的回歸 fixture。

UI：
首次加入 -> 學習 -> 退出 -> 恢復 -> 完成 -> 字典；
考試建立與去重、未知字逐次回報（Beta 系統分享／正式版 HTTPS 分別驗收）、作答後回饋／提前答案曝光、輸入題、字體／VoiceOver。

## 4. 性能與耗電起始預算

以下是工程目標，M2 起在可取得的較舊支援 iPhone 上量測初值並決定是否調整，T028 做正式實機驗收：
- 12k 詞資料下本地 prefix/alias 搜尋 p95 < 150ms。
- 下一題選取不跑全量 forecast；已準備內容切換 p95 < 100ms。
- 回答交易 p95 < 100ms；磁碟錯誤不能被吞掉。
- 冷啟動到可互動 p95 < 2 秒（正式實機，不用 Simulator 結果代替）。
- 在 100,000 個事件資料集仍能正常啟動、查詢和續接；1,000,000 事件作壓測，不承諾所有舊機同速。
- 完整 forecast 不在主執行緒；可取消、節流、重用結果。低電量/發熱時可延後完整重算，沿用安全舊計畫。
- 未執行中的 App 不靠背景常駐維持排程。

不要硬定下載大小再刪掉核心題目；先量測真實內容與索引、TTS/錄音需求。V1 優先系統 TTS，不包大量音檔。[S24]
TTS 的可用離線 voice 依實機已安裝資源核驗，不能承諾任意高品質 voice 第一次開機就離線存在。

## 5. 小型工程驗收與未來可選的真人學習評估

**當前開發順序**：M1 小型合法內容、M3 最小持久化／評分／學習循環可用後，執行 `tasks.json` 的 **T035 內部工程與題目品質驗收**。可用 Xcode／自動化、固定 seed 的模擬情境、題目盲解、一般隨機與高風險內容抽查，不需外部測試者、同學募集、真人跨日實驗或遠端研究服務。**T035 確認重要技術與內容問題處理後即可分批製作正式詞庫**，不等待長期真人成效數據。

**T035 工程檢查重點**：① 每道合格題答案、語境義項與作答後解析一致；② 不因中斷、答案曝光、壞題或跨義項而偽造 FSRS／能力證據；③ 本機事件可保存、恢復、歷史題可解讀；④ 固定使用情境與合理簡單排程基線比較覆蓋、時間成本、未見題消耗及極端負荷；⑤ 內容生產及一般隨機抽查的缺陷在大量生產前可發現、隔離、修正。這是**工程品質 gate，不是記憶科學實證 gate**。若有重大缺陷先修正；若僅缺少真人數據，保持可解釋簡單基線，繼續開發正式 V1。

**真人學習效果驗證可延後**：未來若有合適、自願且符合告知／同意要求的參與者，再執行 T029–T031 的跨日未見題與合理基線比較。**沒有真人受試者不阻擋正式詞庫、離線 App、正式 V1 發布及經隱私驗收的群體研究能力。** 但在沒有此類證據之前，不得宣稱已實證比簡單排程、其他 App 或一般教學更有效。後續真人測試須預先定義指標，控制內容與實際時間、退出偏差；樣本不足就報未知，不把模擬冒充真人效果。

**若未來進行自願真人評估，主要衡量：**
- **主要**：延遲後未見的考試型語境選詞、搭配／短文題表現，按題型、義項／用法與考試需求分層；不把中英翻譯或熟題刷高的分數當成等價指標。
- 達到上述證據所花的有效時間。
- 再次失敗、積欠負擔、預計與實際活動時間差異、合理完成最後一道題造成的超時頻率，以及不同實際投入時長的進展；考前覆蓋比例以原始指定範圍為分母，追蹤未接觸／未驗證項目而不是將其從統計消失。
- 時間預估誤差與預測可靠程度；模型說高把握時是否真的較可靠，且要回報完成者／退出者、有效獨立作答與未獲獨立證據的分布，不只看留到最後的人。
- 內容錯誤/歧義與使用中斷，不歸咎學生能力。

測量需要 train/check family 分離。學習期間問過的 check 題不能在評估時當全新題。

比較「每種能力獨立、逐一維持複習」與「語境選詞為主、減少重複能力檢查、已足夠則降低密集複習、短文取代部分單題」時，應保持**相同投入時間、相近考試範圍與內容品質**。不能在模擬中直接假設長文令全部出現過的字記憶提升，再將輸出當真人成效；既有負荷模擬是成本風險提示，不是最佳策略的實證。
簡單基線與新策略比較時，保持題庫品質、**實際**每日時間、target 難度與起始記憶先驗相近；可在同一位同學的配對內容集做平衡分組，避免把使用者能力差異誤當演算法效果。
同義項跨條件會互相污染，不能任意把近乎相同卡片隨機拆兩組後聲稱獨立。

若未來有條件安排小量自願同學 beta（可延後）：
先使用行為與內容檢查，不宣稱證明學測分數提升。
待有足夠延遲資料，再做事先定義指標的對照；樣本數根據觀察變異与希望偵測的效果規劃，不先硬喊「20 人足夠」。
離線 replay 只能驗證一致性/反事實模型預測，不能直接證明新策略會讓真人學得更好。

## 6. Beta／正式版發布通道及隱私邊界

這是**發行配置的區分**，與 `M0–M6` 的開發里程碑不同；Beta 可以選擇不發布，正式版依獨立 gate 驗收，不能把 M6 的所有任務混成「必須先做真人 beta」。

| 能力 | Beta（可選、預發佈） | 正式 V1（公開發布） |
|---|---|---|
| 離線查字、學習、保存／還原 | 已啟用的內容與核心操作完整可靠，標示預覽限制 | 完整大考中心官方詞表可學覆蓋、全部正式資料／內容 QA |
| 缺詞／錯題回報 | 逐次預覽；使用 iOS 系統分享／郵件草稿或複製文字，由使用者自行送出，不自建回報 API | 專用 HTTPS 內容回報服務（T036），逐次確認、最小資料及存留／安全驗收 |
| 群體記憶研究統計 | **不自動上傳，不設單一聚合方過渡服務**；本機診斷可用於工程 QA | opt-in 後使用經驗收的 DAP／VDAF 多方聚合及 OHTTP／等效來源分離，獨立營運與金鑰權限（T033） |
| 使用者回饋與驗證 | TestFlight 有使用時可收 Apple 平台主動意見回饋，或由使用者自行聯絡；非匿名研究，測試者／真人實驗可完全沒有 | 不需先完成人類學習效果研究，但不能宣稱沒有證據的成效優勢 |
| Gate | T027／T028 中適用的核心資料、內容、無障礙 QA ＋ QA50；缺少正式後端不阻擋 | T037 依賴 T028、T033、T036，另通過 QA51／QA52、正式 CEEC、權利及隱私發布 gate |

**任何 Beta 都不能自動發送學生的原始學習紀錄或自稱以多方安全聚合收集統計。** 系統分享及 TestFlight 反饋是使用者主動向選定提供者送出的可讀資料，可能包含寄件人／裝置 metadata；不應與 lexvane 群體研究同意混用。正式版安全服務未就緒，不能降級為一個只有營運者承諾「不保存」的單方研究 backend。已發布 Beta／本機核心仍然可以運作，但不得宣稱正式版研究交付已完成。

### 本機資料與故障回復（兩種通道皆須遵守）

- 不要求同學提供學校、生日、考卷照片等不必要個資。
- 裝置鎖定保護配合 iOS Data Protection；測試備份／恢復和啟動存取。
- 刪除個人資料清除本機使用者學習資料與相關 caches；不刪 App 內建內容。
- OS／iCloud 裝置備份是系統行為，不能宣稱作業系統完全不會備份。
- SQLite 備份採一致性 snapshot／backup API，不直接複製正在寫入的 main DB 而漏 WAL。[S20]
- 破壞性 migration 前先備份；測試實際復原，不只測產生檔案。

## 7. 同學安裝與發佈

自己的實機可先以 Xcode 安裝。Apple 的 Personal Team 有裝置/佈署限制，不適合作為長期多人 beta 的無成本保證。[S22]
TestFlight 是較正式的同學測試渠道，但需要相應開發者資格；外部測試可能需要審查，build 有 90 天期限。[S21]
App 的離線學習能力不代表 TestFlight 安裝與 build 有效期不受限制。

到發佈里程碑才處理簽名、團隊、合約與實際繳費，由帳戶持有人授權；agent 不自行代付、接受法律文件或更改正式 Team。
測試者若有不支援版本/Android，V1 先不讓跨平台壓垮交付。同步與 Android 在資料驗證後另開階段。

## 8. 正式發布與可選 Beta 驗收

**Beta（可省略）**：符合 §6 的 Beta 能力、適用的核心安全／內容 QA 和 QA50；不需要 T033、T036、多方聚合、獨立回報伺服器或招募真人。**正式 V1**：不得有未解決的資料遺失／錯誤計分 bug，需達成 CEEC 全面可學覆蓋／授權、T035 工程 gate，以及 **T037 對 QA51／QA52 與 T033、T036 的正式發布驗收**；不以招募真人／跨日人類實驗為前提，但學習收益無真人證據時不能作已證明宣稱。
內容清單／授權清單可追溯；對應發布通道的核心學習目標題庫可用；
至少完成一次詞庫升版與備份還原演練；
有裝置性能實測及一段跨日使用紀錄；
已知限制清楚顯示，不把暫缺功能偽裝為「智能已完成」。
