# 05｜詞庫與題庫：內容目標、來源與品質

## 內容目標

**正式 V1 的最低發布門檻**：完整覆蓋**已鎖定版本的大考中心高中英文參考詞彙表**，每個官方詞項都能對應到本機可查詢、可明確加入且有合格核心義項／用法及練習的內容（詞形／別名可映射至穩定詞條，不以重複拼法灌數量）。另外以約 10k–12k 英文 headword 及獨立常用片語集合為內容擴充目標；不能只達成數量卻漏掉官方詞表。須有逐項 coverage audit：來源版本、原始項目、映射 ID、是否可學、被排除的原因與未解缺口；**正式發布前不得有未解的官方詞表缺口**，著作權／授權另通過 gate，不推論「官方公布」就可任意複製釋義與考題。

數量不是主要品質指標。每個可學項目需要足夠的：

- 詞性與重要義項。
- 自然繁中解釋。
- 例句。
- 搭配／用法。
- 詞形／別名。
- 可用於學習與檢查的題目。
- provenance。

先用小型 pilot 驗證內容格式與學習系統，再擴大；**最小學習循環可用後先做小型真人跨日比較，達到 06 的繼續擴充 gate 才大量生成正式詞庫**。小型試用不降低上述正式版本最低涵蓋要求，也不先預先規定固定 pipeline stage。

內容在開發階段建立、審查、版本化後打包進 App，不在 runtime 生成。參考流程（具體階段與格式由 content tooling 依規模設計）：

```
來源與授權 gate → headword / phrase 清單 → 自有穩定 ID → 義項與用法整理
→ LLM 生成候選 → LLM 全量審查 → 題目盲解與歧義審查 → 程式驗證
→ 人工高風險抽查＋一般題隨機抽查 → 版本化內容包 + provenance
```

## V1 義項與用法優先度：簡單分級

為了避免每個字的全部義項都變成必須長期維護的複習義務，內容包對**適合教學的義項／用法群**提供有來源、可修改的起始優先度：

- **基礎優先**：多數學生理解該字／常見高中考試語境需要的義項或用法；不一定是字典第一義，也可能不只一個。
- **常用補充**：重要第二義、常見搭配或其他有額外價值的情境，在負荷與考試需要允許時逐步加入。
- **延後學習**：較低頻或較低優先的內容仍可在字典查到，但不預設產生密集複習義務。

這是編輯上的**粗分級 prior**，不是逐義項的精確出題機率。實際優先順序仍受學生指定的考試範圍、考試需求與作答證據影響；只有老師提供的英文清單時不能假裝知道該次指定哪個罕見義項。

V1 不先建立歷屆考題大規模擷取、逐校逐年的統計平台。用合法的官方分級、一般詞頻、適齡語料，以及一小批有代表性的考題分析／人工覆核，修正明顯遺漏與錯誤即可。題庫某義項出現次數為零，**不代表它永遠不必學**。

## 資料來源方向

### CEEC

大考中心高中英文參考詞彙表很適合作為台灣高中 coverage / priority 參考。[S01][S02]

但它不是完整雙語詞典，也有實際使用／再散布條件。是否可用於公開、營利或開源內容包，需要依實際授權確認；不能因為 beta 免費就推論所有未來用途都沒問題。

### Open English WordNet

可作 sense、part-of-speech、semantic relation 的參考候選。[S16][S17]

它的 sense granularity 不一定適合高中學習，因此只作來源，不要求 UI 原封不動呈現。

### 其他頻率資料

wordfreq 等可以作候選排序，但要分清楚程式碼授權與資料授權。[S18] **一般詞頻不等於詞義頻率，也不等於台灣高中出題機率。** 詞義粗分級可以從來源詞彙分級、常見用法與審查理由出發，而不是為每個詞生成精確機率。

分析考題時可區分「直接答案／重要選項」、「理解篇章必需」與「文章中偶然出現」，但 V1 不要求完整標註所有歷屆題。分析、保存、改作、散布考卷和原文前仍須進行授權 gate；不能假設交給 LLM 轉成標籤就一定沒有著作權問題。

### 自建內容

繁中解釋、例句、搭配與題目可以由專案自行撰寫，或用 LLM 大量生成／審查。

AI credits 可以積極使用在 build-time；App runtime 不需要 LLM。

## Provenance 是硬需求

至少要能回答：

- 這個欄位／題目從哪裡來？
- 用了哪個版本的來源？
- 來源授權是什麼？
- 是直接取用、改寫、人工撰寫還是 AI 生成？
- 如果由 AI 生成／審查，用了哪個模型／prompt 版本？
- 後來是否被人工修正？
- 如果來源需要換掉，哪些內容受影響？

具體用 SQL、JSON、metadata tables 還是其他表示，由 content tooling 實作時決定。

## AI 可以做什麼

適合：

- 將來源 sense 整理成適合學生的教學義項群，記錄粗分級、來源和審查理由；不直接把字典第一義當成唯一基礎義。
- 生成繁中解釋、例句、搭配與題目候選。
- 第二模型／不同 prompt 交叉審查。
- 隱藏標準答案後重新解題，找出多解。
- 標記過難詞彙、語法問題、可疑搭配與重複 sense。
- 對 10k+ 詞做大規模一致性 review。

AI 不應被當成：

- 授權判斷器。
- 100% 正確的唯一審稿者。
- 可以把受限來源「改寫一下就變乾淨」的工具。

LLM judge 有已知偏差，因此需要程式檢查、來源核對、人工高風險抽查，**也要隨機審查未被模型標記為可疑的一般題**，避免 AI 共同盲點與只看難題的抽樣偏差。[S19]

## 題目品質目標

每個真正用來估計 mastery 的題目必須盡量做到：

- 有明確 primary target，區分「看到英文猜字義」與「句子留空時選出正確英文詞」；兩種題不能冒充彼此的成功證據。
- 答案唯一，或列出所有可接受答案；語境克漏字的干擾項要合理，不能產生多解。
- 不靠選項長度、詞性明顯不符、荒謬干擾項等方式洩漏答案；理解目標詞／用法才應有明顯作答優勢。
- 題幹語境真的使用目標義項；利用題目本身的上下文推論是合理解題能力，額外提示與已看答案後的成功則另行記錄。
- 不把同一句只換人名當成新的 transfer evidence。
- learning/training 題與用來驗證 transfer 的題目有所區隔；最終小型真人檢查題至少有一批由相對獨立的撰寫／審查流程提供，不能只是在同一套 LLM prompt 產生的題目換字。
- 有疑義時寧可 quarantine，不要把內容錯誤算成學生不會。

具體一個 target 要幾道題、怎麼分 train/check，應先由 pilot 的實際重用率、跨 family 干擾、**未見檢查題庫存消耗**、人工抽查缺陷率與學習驗證決定，不在規劃階段固定數字。練習題可合理重複，但一旦展示的檢查題不能重新標成未見；沒有新檢查題可以繼續做練習，**不可冒稱又取得未見遷移證據**。先估可持續供題能力再放大目標數。

## 內容版本

內容更新不能讓學習歷史失效。

- 只改文字表述，可保留 identity。
- sense 的實際語義被拆分／合併時，要明確做 mapping 或要求重新驗證。
- 壞題撤銷後，相關 evidence 應能被排除或重新計算；**教錯的知識不會隨著刪掉 Good 而從學生腦中消失**。若內容曾傳授錯誤義項／搭配，升版需追蹤受影響學習目標，安排適當更正、正確例句及必要的之後確認，不把更正當學生自己答錯。已展示題目必要快照與歷史可解讀性依 02。
- 換詞庫供應商不應直接等於「所有使用者重新開始」。

## 內容完成條件

一個正式內容包至少要：

- 來源與權利狀態可追溯。
- 搜尋／別名不產生未處理的重大碰撞。
- 核心義項與用法可讀、自然、符合目標程度；優先分級有來源、理由且能被修訂。
- 真正啟用的 learning target 有足夠合格題目。
- 有自動檢查、AI review、一般隨機抽樣及高風險人工審查紀錄；有受限用途且相對獨立的未見檢查題。
- 能產生版本與變更報告，**逐項官方 CEEC 詞表版本映射／覆蓋報告**、題目供應及撤銷／更正對學生的影響紀錄。

內容工具的具體流程、檔案格式與並行方式由 agent 根據實際規模設計。
