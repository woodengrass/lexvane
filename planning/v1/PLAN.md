# lexvane｜V1 主計畫

版本：1.4｜日期：2026-10-11

本文件是摘要與索引。細節只寫在下表的「唯一來源」，這裡不重複；兩者不一致時以唯一來源為準。規格只寫要達成什麼與驗收，怎麼做由實作決定；可參考的做法集中在 `docs/08`。

## 產品目標

iPhone-first、離線的英文詞彙 App，對象是台灣高中生。**目標是在每日可用時間、指定考試範圍與期限內，提高學生在未見、具代表性語境題的答題表現；沒有期限時提升長期有用的詞彙能力。** 記憶率、字數、完成率都只是規劃與評估用的代理指標。

使用者只做四件事：查詢或貼上英文、明確按加入、設定每日時間、視需要建立考試（日期、是否需要英文書寫）。其餘由系統負責日常選題、考前覆蓋、新舊複習與適合的記憶排程；未驗證的動態 retention 不必先成為預設。沒有 Again/Hard/Good/Easy，也沒有自評熟悉度。

## 不可違反的核心規則

1. 核心完全離線；無帳號、無 runtime LLM、無 OCR、無同步。（01）
2. 查字不等於加入；大小寫永不扣分；未收錄字不能直接加入，可外連 Cambridge，**另有逐次確認的缺詞回報**。正式考試範圍中未收錄項不能隱形消失。（01）
3. 主力題型是「句子留空、從英文選項選詞」；看到英文猜詞義不能冒充選詞能力。（03 §1、§4）
4. 不同義項、辨認／產出證據分開記錄，但不讓每個能力都產生獨立的永久複習義務；同一題不算多次成功。（03 §2）
5. **正式 V1 不做作答前額外解題提示，必須做好作答後正解／用法／錯因回饋。** FSRS-6 是可重現的首版記憶模型基線；答對／錯誤映射 Good／Again 是版本化 adapter，不得覆蓋原始作答事實。未提交、解析曝光、無法計分都不能冒充成功或失敗。（03 §4、§6）
6. 平常每日時間可隨時調整，也可只改今天；它是**預計安排量，不是截斷正在作答題目的秒數上限**。長期投入不足（即使無考試）要適度提醒，不暗改預算；積欠不強迫補完，不縮小原始考試分母，排程須通過含中斷／變動時間的模擬驗收。（01 §4–6、04 §2、§9）
7. 記憶模型狀態在本機更新；**動態目標 retention 和個人模型參數重新擬合，是需要相同條件下比較才能預設啟用的候選策略**。未有增益證據就維持可靠的簡單版，不因高 retention 或模擬表現好而宣稱真人教學已最佳。（03 §6、04 §3）
8. 原始作答事件是唯一真相，其餘狀態可重算；詞庫與使用者資料分開，詞庫升版不重置學習。短期中斷能續題，停滯過久僅換未完成題，不把換題當答錯或新成功。（01 §6、02、03 §4）
9. 個人資料與個人模型只留在裝置；**自願群體研究是正式版重要交付能力**，但只有 opt-in 與相應統計可信度／隱私 gate 通過後才能上傳。個人主動回報缺詞是另一條限目的資料管線，不能互相沿用同意；核心離線學習不受影響。（privacy-data-collection.md）
10. **正式 V1 最低內容門檻：完整涵蓋已鎖定版本的大考中心高中英文參考詞彙表，且對應項目可查、可加入、有合格核心教學與練習**；官方 coverage 和授權須逐項驗收。小型 200 詞 pilot 是提前驗證，不是正式版的替代品。（01 R03、05、06 QA42）

## 里程碑

| 階段 | 完成後能做什麼 | 不在這一階段做 |
|---|---|---|
| M0 開發基礎 | Xcode 可建置、測試可跑、本地持久化已驗證、依賴可重現、技術決策有紀錄。 | 學習算法、漂亮首頁、全量生成、帳號同步。 |
| M1 內容 pilot | 200 詞 + 30 片語可教、可查、可生成合格語境題與正確回饋；內容包可重建、保留未見評估題。 | 完整官方詞表、全題庫、完整考古題統計平台。 |
| M2 離線字典與資料安全 | 查字、一鍵加入、批次匯入、local persistence、可備份還原。 | 學習效率模型的高階訓練。 |
| M3 核心學習循環＋**早期真人 gate** | 可追溯作答、版本化 FSRS 基線、正確回饋與續接；**T017 最小循環可用後即做 T035 小型真人跨日試用／合理簡單基線比較**，決定是否修正測量與內容再擴充。 | 大量完整詞庫、完整 forecast、遠端研究、強制啟用動態 retention。 |
| M4 自動規劃 | 平常／當日可變時間、未完成後重新規劃、長期投入不足提醒、考試 forecast／負荷；本機進階擬合與動態 retention 僅作候選驗證。 | 必須啟用精密習慣預測／個人模型才可交付，CloudKit、Android、付費。 |
| M5 正式內容與可靠性 | **T035 gate 後**逐項完成大考中心詞表全涵蓋及約 10k–12k 擴充，內容更正、歷史備份可解讀、主動缺詞回報與實機驗收。 | 未經驗證先大量生成、對外宣稱已證明提升學測成績。 |
| M6 beta 與校正 | 純離線 beta 可先測跨日與未見題效果；另完成有限記憶／耗時統計的自願群體研究管線與分級隱私驗收。 | 大型自適應模型、未經 opt-in 或正式安全聚合 gate 的研究上傳。 |

- 執行主線：M0 → M1 → M2 → M3（**T017 後盡早做 T035 小型真人跨日 gate，可在 M3 其他獨立工作仍進行時開始**）→ M4 → M5 → M6。**T025 正式內容擴充依賴 T035 決策通過**；若內容／測量失效先修正重測，證據不足的高階策略保留基線、不妨礙核心交付。內容 pipeline 在 pilot 稳定後可與 App 開發並行，正式全面擴充不得跳過 T035。
- 里程碑以驗收為準，不承諾天數；資料授權、全量內容審查與真實延遲測試可能比寫 UI 更慢。
- 36 個任務的依賴與驗收只寫在 `contracts/tasks.json`。依 `depends_on` 決定順序，同一 milestone 內沒有依賴的任務可並行。
- 一次只做一個 milestone，完成後回報再進下一個。第一個入口：`agent/START-M0.md`。
- 多 agent 協作：分工由主 agent 決定；schema/migration、lockfile、Xcode project 等共用檔案同時只有一個寫入者；獨立驗收先看資料完整性與錯誤評分。

## 後續階段（V1 不實作）

P1 Apple 裝置同步：真的有多 Apple 裝置需求後再做 CKSyncEngine adapter、account lifecycle、衝突與離線合併演練。[S12]
P2 Android/桌面：依實際測試群決定 client 技術與中立 backend；共用內容 ID、事件 contract、政策 test vectors。不可讓两个獨立雲都掌管同一份狀態而沒有合併規則。
P3 進階個人化：T032 是 V1 可退回的本機候選評估，不作核心交付強制 gate；真正替換 FSRS／學習策略需後續真人驗證，候選見 `docs/08`。
P4 收費/開源：分離 code/content 授權；不把營運決策塞入 V1 核心架構。

## 尚未決定、但不阻擋 M0

- 內容來源的實際授權（M1 T005 前確認）；CEEC 等有條件的資料不能把「免費測試」當通用豁免。
- 未成年人同意與法律確認（beta 發佈前）。
- Apple 開發者帳號、簽名與費用（發佈階段由持有人處理）。
- 群體參數如何只由統計結果算出（M6 再設計）。
